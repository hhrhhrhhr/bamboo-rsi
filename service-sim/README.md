# AI 服务对话 RSI 模拟

在 `collections-lab` 固定业务评测和 `service-feedback` 审核队列之上，增加真实 SystemOne 调用。模型分别扮演虚构客户、客服、模拟运营和候选选择器。三个波次各 120 位虚构客户，每波 60 位用于训练、60 位用于独立验证。每完成 20 条训练会话再集中模拟运营审核。

这是有限、离线的工程试验。客户与运营都是模拟角色，**真人审核和真实客户联系均为零**，不能据此宣称满意度、还款率、生产收益或正式商业可用。不给真实客户打电话、不访问业务数据库、不发布生产话术。已有待真人审核队列必须使用另一个路径保留。

## 执行

依次安装 `rsi-core`、`rsi-sdk`、`rsi-http`、`collections-lab`、`service-feedback`、本包。传入用户授权的 SystemOne 地址和固定模型标识，不需要或读取其他服务的密钥。

```powershell
bamboo-service-sim --destination .runtime/service-ai/campaign --endpoint http://127.0.0.1:8090/v1/systemone --model YOUR_PINNED_MODEL --simulate-operator
```

默认最多 2,400 次 HTTP 尝试、1 小时、单请求 30 秒。批处理可用 `--timeout` 配置 1–180 秒，冻结后不变；这是离线服务模拟，不适用于实时游戏控制。请求超时受剩余总时长限制。每次先持久预留预算；失败不返还、不自动重试，并停止本次试验保留证据。存在的 campaign 拒绝覆盖或悄悄重复。后续开发重跑必须另建目录、绑定此前预算并扣除已用额度，不能用新目录清零任务预算。`provider/STOP` 或 `workflow/STOP` 可停止后续动作。这里只发送虚构文本，不跟随重定向，不转发云凭据。

## 改进、验证和继承

1. 模型从预置的自然语言选项中选择客户表达、服务意图和有边界的后续动作。它不是自由文本生成器。客户开场的三个选项是同一需求的等价改写，记录模型实际偏好；这不授予执行权限。业务分类、运营和优化器决策低于 0.70 置信度时仍拒绝确定性判断。
2. 模拟运营仅看训练会话原话和实际回答，选择确认、拒绝或补充材料。猜测心理状态不能成为事实。未经确认的记录不能学习。
3. 经验搜索根据已审核反馈生成字面路由提示和话术选择补丁；真实模型决定是否提交验证。没有证据就保留父版本。
4. 对新验证客户，父版本与候选分别发起新的模型调用，交替执行 12 组。固定评测计算服务损失、处理完整度、显式重复/澄清、停止和人工偏好违规。
5. 主指标至少改善 10%、其他指标不退步、安全与偏好违规为零；保持既有配对检验和逐波次阈值分配。候选不能修改评测器或阈值。
6. 协调器按评测决定接受或拒绝；下一波探索、候选生成都从实际接受的父版本继续。审核过期或撤销会阻止新使用及晋级。

相同模型扮演多个角色、共享模板和固定回复库都会产生偏差；客户场景限定为获取可核验的处理途径，不要求模拟器返回真实金额或到账事实。这个门槛只说明当前离线工程基准，不能泛化到真实人群。不是模型权重自训练，也不是任意代码自修改。

## 证据与回归

`report.html` 展示每波结果与展开式对话；`report.json` 给出预算、版本血缘和范围；`provider/calls/` 保存实际请求/响应或失败；`operator/` 保存模拟审核原始调用；`workflow/jobs/` 保存预登记计划、候选、双重构建、独立验证和晋级依据。`accepted-bundle.json` 是供审核的离线导出，不自动写入 aichatcore。

冷重启会重新核验冻结代码、版本和原始证据。测试命令为 `python -m pytest service-sim/tests`（或在本目录执行 pytest）；单元测试使用明确标记的 test double，不能算实测模型样本。
