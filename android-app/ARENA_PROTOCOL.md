# 独立评测证明协议

这是待授权评测平台实现的适配契约，不是腾讯官方接口。应用不分发评测私钥，不提供将模型自报结果转成可信实机证明的功能。

## 预登记与采样

登记后保存试验 ID、父/候选哈希、固定 200 槽位计划、运行上下文哈希和独立公钥。证据 ZIP 的 rsi-snapshot.json 包含计划。评测服务必须另行验证授权、设备/应用身份，安排可配对对局，控制英雄、地图、对手策略、随机条件与阵营。对手 ID 须标识冻结的对手版本，不能仅用昵称。

reserve 先消耗槽位再运行。中断保留 UNKNOWN，不能覆盖、补录成成功或挑选更好的重试结果。未知、无录像、输入未释放不能成为有效样本；应拒绝试验并保留失败，再登记完整新试验。

服务必须通过独立观测确认胜负和开发介入情况。仅照抄客户端报告再签名，不构成独立评测。

## JSON 格式

顶层包含 body 与 signature。采用 P-256 ECDSA / SHA-256；DER 签名字节为标准 Base64，公钥为 Base64 X.509 SubjectPublicKeyInfo。正文至少包含：

| 字段 | 类型与来源 |
|---|---|
| run_id, policy, trial, context_sha256 | 与 assignment 完全一致 |
| pair, swapped | 编号整数 0–99、阵营布尔值，与计划一致 |
| origin | authorized_arena_live |
| assisted | false；任何开发代打/干预必须如实标记 |
| issued_at_ms | 签发时刻，不早于预留，不能超过手机当前时间 30 秒 |
| match_id, opponent | 平台可追溯身份，1–128 位字母、数字或 ._:- |
| outcome | WIN 或 LOSS，与独立观测和本地 OCR 一致 |
| calls, duration_ms | 整数，与本地记录一致 |
| trace_sha256, video_sha256 | 实际文件 SHA-256，与封存报告一致 |

CanonicalJson 按对象键升序，保留数组顺序，UTF-8、无多余空白；字符串用 JSON 转义。上述数字用整数，不能替换成浮点写法。签名覆盖整个 body，包括额外字段。接入前用非生产测试向量验证双方规范化字节兼容。

手机导入时重新计算录像与日志哈希，再校验签名和冻结公钥。重复运行、重复比赛 ID、错版本、错配对、未知结果、无完整录像会被拒绝。全部 200 局满足后才公开比较结果并晋级。

## 信任边界

本机 HMAC 不能替代设备可信认证、远端审计和防重装重放。操作员可以配置自己的公钥，所以本机“晋级”不能直接作为第三方商业认证。商业评测须固定可信身份，由独立服务保管私钥和原始观测，并使用游戏方批准的环境。

尚无远端签名服务、自动排队/编组接口、设备认证或商用服务部署。不得用单元测试的临时密钥生成实机证明。测试只验证程序状态转换，不证明现实改进。
