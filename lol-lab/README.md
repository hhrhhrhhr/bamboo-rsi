# LoL Lab：Decision + 有限动作 + 策略 RSI

Windows 英雄联盟独立实验模块。Decision 根据游戏窗口截图和本地 Live Client 遥测选择目标与有界技能；本模块执行有限键鼠动作，记录失败，再由 Decision 从受限策略空间提出候选。复用 `rsi-core` 的不可变版本、证据绑定晋级、父版本继承和回滚。

**当前是固定场景的实验实现：已在实机验证关闭暂离提示、升级技能和部分出基地导航，尚无真实补刀、英雄交战、对战获胜或 RSI 晋级验收。** 离线测试不代表会打完整对局、不代表能获胜，也不代表商业发布就绪。不会创建大厅、排队、登录或自动重开。进入下一局需要操作者完成，局内介入会令样本失败。首版的递归对象是策略 JSON，未接入 LoL 专用 Codex 代码补丁优化器，不更新 Decision 模型权重。

## 首版范围

- 自定义电脑对手场景：自己盖伦、默认蓝方、对面一个盖伦电脑；只有自己一个真人。固定召唤师峡谷，游戏时间 00:30–05:30。模板可在初始化前指定另一电脑英雄或阵营，但同一实验内冻结。匹配/排位及有其他真人的房间不符合场景，会停止。
- 执行器实现移动、攻击移动、Q/W/E/R、升级技能、回城、镜头回中、等待、停止；当前 Decision 菜单开放的动作见下条。格点仅覆盖客户区的有限区域；普通施法及默认 QWER、A、B、S、Ctrl+技能、空格键位是前提。未实现购买装备、精确走砍、召唤师技能或完整战术。首轮两组均不买装备，保持相同默认符文、电脑难度和客户端设置；这些条件部分仍需操作者保持，Live Client 不提供全面证明。
- 一般动作 250/400/600 ms；上路导航、沿可见道路前进和回基地为该时长的五倍（最多 3 s），Q 近身攻击为两倍（最多 1.2 s），兵线攻击移动为三倍（最多 1.8 s），回城最多 8.2 s；动作后发 S 停止，模型等待期不持续移动。决策与截图合计超过 2 秒则等待；连续三次调用失败停止。技能等级、低血量、死亡、时钟回退和名单变化都有检查。
- 当前 Decision 菜单按技能点阶段切换：有技能点时选择加点或处理明确的暂离弹窗；否则选择前往外塔集结点、沿可见道路继续前进、向可见兵线攻击移动、Q 近身攻击、W 防御、E 近身攻击、短距离避让、后撤、回城、等待或停止。Q/W/E 只在已学习时开放，冷却与 E 是否已启动由当前画面判断；尚无可靠的技能效果核验。R 的格点精度不足，暂未开放给模型。
- 定向移动和攻击同时要求模型选择全图中的一个目标格，缺失或无效位置转为等待；不再用固定画面坐标代替敌人位置。攻击移动可能选择目标附近的另一敌方单位，不能保证精确攻击指定英雄。目标点击完成后才让镜头跟随，避免先移动镜头改变坐标。固定集结点仅用于到达蓝方上路外塔，仍要求 16:9、默认小地图布局；新动作尚待实机验收。
- 导航菜单依据当前可见场景区分基地与上路道路，不要求从单帧猜测是否已经到过外塔。位置问题独立依据可见敌人、安全道路和风险选择，不依赖另一道技能题的答案；不需要位置的动作会忽略该选择。此问题设计尚待真实画面验证，不强制选出动作或放宽置信度。
- 目标选项同时给出“上排·正中”等方位名称和全图百分比，仍映射到原有 15 个固定格点；不移动格点或加入默认点击。空路前进可参考小地图的蓝方至红方道路方向，点击目标仍必须在主画面可见安全道路上。该描述方式的定位效果尚未验证。
- 下一次决策接收最近两次动作后的实际遥测及补刀、击杀、死亡、助攻、己方血量和等级变化，以及连续相同动作次数。无得分变化不等于卡住，也不能说明没有伤害；发出攻击按键不算命中证据。位置选择与原始模型响应绑定，独立评测器拒绝改写目标的记录，20 对正式对照及晋级要求保持不变。
- 每次遥测请求前后核验本地 2999 监听端口唯一属于输入绑定的游戏 PID。旧进程残留或端口归属不明时停止，防止新画面配上旧对局数据。
- 局内请求使用 6 秒网络超时；不涉及实时输入的策略提案使用 15 秒超时。接口能返回结果不等于实时延迟合格：慢响应只能作为提案或诊断，不能放宽动作时效来冒充可用。
- Decision 请求复用经过证书验证的 HTTPS 连接；禁止重定向，响应大小和读取耗时受限。结束或异常后关闭连接。网络依赖版本与 Python 版本也纳入冻结指纹。
- 只向绑定的前台游戏窗口发送标记过的普通 Win32 输入。不切前台、不提权、不读取进程内存。游戏或反作弊拒绝输入会留下失败，需要另行确认支持的执行接口。
- 启动前只读检查执行进程和游戏进程的完整性级别。游戏权限高于执行器时预检失败，不消耗对照槽位；读取失败也停止。需要用户通过正常 Windows 授权启动同权限的执行进程，程序不会绕过系统授权或自动提权。
- 先启动仅游戏窗口的无麦克风录像，再启动输入。外部键鼠输入、窗口切换、最小化、尺寸变化、STOP 文件或异常会结束试跑。停止后释放按键、关闭录像并完整解码核验。原始 MKV、PNG、遥测、决策及摘要关联到同一 run ID。
- 游戏画面通过 Windows Graphics Capture 绑定准确 HWND 获取，编码为 5 FPS 视频。采集线程和校验线程均使用物理像素坐标；拒绝黑屏、接近纯色、尺寸不符或陈旧帧，不改用桌面截图。编码前先通过画面检查，避免对黑屏调用模型。
- StartLux 图像请求按首轮最高概率以 0.92 为门槛触发自动思考，最多 64 个思考 token。服务用于触发思考的概率与返回置信度不同，因此触发门槛略高于执行门槛。此设置属于待验证的运行配置：返回置信度与所选概率仍须均达到 0.9，并通过两秒画面时效检查，不能把思考完成视为动作可用。文字策略提案保持独立的请求配置。
- StartLux 的兵线动作菜单同时提供未加标注的全图和同帧辅助视图；辅助视图裁剪全图横向 8%–92%、纵向 0%–72%，叠加 15 个候选格的编号及十字，帮助模型把选项对应到位置。标记是程序生成的点击位置索引，不是检测到的敌人或推荐目标；游戏事实以原图核实，标记遮挡时回看原图。加点菜单仍只使用全图。原图、实际发送的辅助图、裁剪范围、标记坐标及哈希一同保存，失败调用也保留。此定位方案尚未通过模型或实机验收；处理与存证耗时仍计入原有时效检查，不改变位置、置信度或晋级条件。

低层输入监测用于记录本机人工介入，不是抵御恶意本机管理员的安全边界。归档哈希可以发现未同步改写的证据变化；该模块没有第三方签名、公证或外部裁判服务。模型接收去掉账号字段的遥测，但游戏截图可能含可见昵称；全部原始资料仅保存在忽略的本机 `.runtime` 中。

## 启动

Jev 1.14 可从 `examples/config.jev.template.json` 配置。Bamboo 的 Jev 专用路由是
`https://api.bamboonode.dev/jev/v1/decisions`，模型为 `typesafe/jev-1.14`；
`/v1/decisions` 是 StartLux 路由，不能混用。路由信息来自网关公开的
[模型与协议配置](https://api.bamboonode.dev/api/pricing)。Jev 需要账号额度，
StartLux 免费测试的说明不适用于 Jev。

Jev 图像采用上游说明的 `state` 数组和 `image_url` 数据 URI；不发送 StartLux
专有的 `images`、`think_mode` 等字段。每道选择题增加明确的弃权选项，仍要求置信度
和所选概率均至少 0.9；弃权、低置信度、缺失选项或模型身份不符均不会发出动作。
保持两秒画面时效与原有实机对照条件。Jev 与 StartLux 必须分别冻结实验，不能把二者
样本混合晋级。参考 [上游图像格式](https://openrouter.ai/blog/insights/what-is-jev/)。

目前 Jev 仅完成路由发现、额度检查和离线协议回归；实际推理被零额度响应阻止，
图像透传、返回模型身份和实机延迟尚待验证。`decision_quota_exhausted` 表示额度不足，
不会记录返回正文中的密钥或账号数据，也不会自动充值或切换模型。

使用 Python 3.12 及以上版本，保持原神运行环境隔离。依赖为本仓库 `rsi-core`、`delta-lab` 的协议/视频校验工具、`psutil==7.2.2`、`httpx==0.28.1`、`windows-capture==2.0.1`（Windows）、`numpy==2.5.4`、`opencv-python==5.0.0.93`。`run.ps1` 只为本次子进程设置模块路径；本地可将新依赖安装到独立 `--target` 目录并仅为 LoL 进程加入模块路径。

1. 将 `examples/config.template.json` 复制到 `.runtime/lol-lab/config.json`，填写游戏 EXE、FFmpeg 和 Riot 根证书的绝对路径。FFmpeg 需要 `libx264` 编码及 Matroska 支持；画面由 Windows Graphics Capture 提供。
2. 从 [Riot 官方说明](https://developer.riotgames.com/docs/lol#game-client-api_root-certificatessl-errors) 获取根证书。程序验证 TLS，不跳过证书检查。游戏遥测固定读取 `https://127.0.0.1:2999/liveclientdata/allgamedata`，不通过代理。
3. 通过当前进程环境或自己的安全启动器提供 `BAMBOO_DECISION_KEY`；不要把密钥放进配置、命令行参数、Git 或报告。默认 Decision 地址为 `https://api.bamboonode.cn/v1/decisions`。
4. 初始化前确定预算。模板的 500 次仅适合开发试跑；40 个正式样本加开发需要更多预算。策略请求每秒最多约一次、每轮最多 500 次，全局上限 20000。预算写入冻结实验，调用预先扣计，失败不退。提案另限 8 次。不要为绕过耗尽预算复制或重建同一试验。

仓库根目录执行：

```powershell
& .\lol-lab\run.ps1 doctor
& .\lol-lab\run.ps1 init
& .\lol-lab\run.ps1 step -WaitSeconds 180
```

`doctor` 不发输入、不调用 Decision、不消耗试验槽位。`init` 冻结代码、配置、游戏 EXE、FFmpeg、证书和第 0 代策略。`step` 根据记录自动选择开发试跑、提出候选、正式试跑或评估晋级；开始游戏阶段最多等待指定时间，期间切到新开的固定电脑对局，00:30 前就绪。开始输入后请勿操作键鼠。每次新对局调用一次 `step`；本版不负责局间重开。

错过 00:30 时，可显式使用 `diagnose -WaitSeconds 300` 诊断当前电脑对局。从录像启动后的实际游戏时间起记录完整五分钟，其余名单、输入、录像及预算检查保留。此模式写入独立的 `lol_windows_diagnostic` 来源和 `diagnostic` 分配，不计入标准开发样本、正式对照或晋级，也不能在已登记对照期间运行。等待开局期间同样响应 home 中的 `STOP` 文件。

`run.ps1` 的默认 home 是 `.runtime/lol-lab/experiment-v1`，可用 `-Home` 指定其他独立实验目录。初始化后不能修改冻结文件，版本更新也会导致实验停止。先结束当前执行并核验输入释放，保留旧证据，再为新的部署建立独立实验；不把跨游戏补丁的样本拼成一个试验。

其他命令：

```powershell
& .\lol-lab\run.ps1 status
& .\lol-lab\run.ps1 run -WaitSeconds 180              # 开发试跑
& .\lol-lab\run.ps1 propose                          # 自动请求策略候选
& .\lol-lab\run.ps1 run -Prospective -WaitSeconds 180 # 按预登记顺序收集一局
& .\lol-lab\run.ps1 evaluate
& .\lol-lab\run.ps1 recover                          # 保留中断；不会重试已用槽位
& .\lol-lab\run.ps1 reject -Reason '记录拒绝原因'
& .\lol-lab\run.ps1 rollback -Reason '记录回滚原因'
```

主动中止可按 Ctrl+C，或在实验 home 创建 `STOP` 文件；检查录像保存和 `input_released`。移除 STOP 前先确认已退出。崩溃后若输入状态不能确认，`recover` 要求旧执行进程、游戏进程及关联录像进程退出，才解除中断标记；不假称异常退出已释放输入。

## RSI 验收规则

基础战斗需要先单独验收。当前执行器会从同一张原始画面中的短暗条和红色像素生成疑似小兵位置，交给 Decision 确认和选择；这些候选可能漏检或误检，不能当作敌人真值。原图始终保留，辅助图中的 `c` 编号与归一化坐标逐一绑定。没有候选时使用四个不同方向的画面格点；模型弃权时不补选目标。视觉候选只允许用于有界的 `farm_wave`，不用于英雄 R、导航或撤退。

每次动作后记录 `action_observed`、新截图、原始遥测和补刀/击杀变化。下一次 Decision 可读取反馈；独立评测器从原始响应、画面和遥测重建坐标及效果，拒绝篡改或缺失的反馈。`basic_combat` 区分攻击按键与本账号补刀证据：自身掉血、敌方血条减少或动作超时都不能推断自己造成了伤害。即使出现补刀，也仍需回看连续录像确认完整接敌过程，不能直接宣称英雄交战、胜局或 RSI 晋级成功。

配置可选 `decision_transport: "system"`（默认系统代理）或 `"direct"`（直连同一服务）。传输方式随部署冻结；不自动切换、不关闭 TLS 验证，也不放宽置信度和画面时效。网络诊断不是模型就绪或实机验收。

自托管 `/v1/systemone` 使用显式 `decision_protocol: "systemone"` 和 `decision_transport: "direct"`。`model` 填服务实际返回的完整标识，并冻结在实验中；请求不传 `model` 或任何 Authorization/Bamboo 密钥，响应仍必须匹配冻结的模型标识。HTTP 仅接受内网 IPv4 或回环字面地址，公网使用 HTTPS，禁止重定向。原有云端 Jev、StartLux 路由规则保持不变。

SystemOne 适配器使用带 `<image>` 标记的 `state` 与 `images` 数组，保留原始图和候选标注图。服务必须实际启用这套图像输入；文字请求成功不能证明视觉能力。部署前先确认图像能力，再做三张不同真实画面的有预算恢复检查。HTTP 429 计为已消耗的服务失败，不在 HTTP 客户端内部重试；执行期间沿用 2 秒、4 秒退避和连续三次失败停止。示例 curl 的 180 秒等待不适用于游戏动作，实机仍执行原有时延、画面新鲜度与置信度门槛。

1. 当前已接受父版本至少有三次带原始资料的开发尝试；失败也保留，介入标记如实传给优化器。正式对照期间禁止追加开发局。
2. 提案前登记 20 对、40 个槽位，每对基线/候选顺序随机。模型只看到父版本的开发记录，看不到对照数据。候选每次仅更改撤退血量、动作时长或策略偏好中的一个字段；不能改变评测器、代码、动作边界或预算。
3. 每次槽位先保留再执行；中断或实机失败拒绝本候选，不换一局覆盖。预检未通过尚未开始，不消耗槽位。每个游戏进程仅用一次，合成运行、人工介入和残缺录像均不可晋级。
4. 收齐后从原始遥测重算补刀与死亡：候选累计补刀至少多 40 且提升至少 5%，总死亡不增加，模型调用量不超过基线 110%。配对补刀差做单侧符号检验，按第 n 个提案采用 `0.05 / (n*(n+1))` 的阈值，避免反复提案后挑一次好结果。游戏随机性未受控，因此是固定场景的有限证据。
5. 完整通过才用 CAS 晋级；下一轮版本和开发证据必须来自已接受的父版本。晋级报告只代表这段五分钟对线指标改善，不能解释为完整对局胜率改善。代码保留回滚历史。

无需改动原神的 14 天委托对照：LoL 使用独立 home、预算、版本、输入租约和评测。它展示同一个 RSI 存储核心接不同游戏适配器的方式，但“通用 RSI 可稳定用于任意游戏”仍需不同领域的实证。
